# FX graph regions and capture coverage

## Refactor scope

This refactor is limited to graph analysis and graph transformation used by action generation, and should live almost entirely in `growingnn/utils/fx/`. It covers how captured FX graphs are represented, analyzed, annotated with tensor interfaces, searched for nested regions/action sites, and edited at explicit node/edge boundaries. Changes to `TracedModel` and existing action generators should be small compatibility adapters needed to use these shared FX facilities. Model loading, training, action policy/registry design, and wholesale rewrites of action semantics are outside this scope. No block duplication or block deletion actions are being added.

## Existing analysis path

`TracedModel.create(model, input_shape)` historically called `torch.fx.symbolic_trace`. An FX graph contains placeholders, `call_module`, `call_function`, `call_method`, `get_attr`, and output nodes. Standard modules may remain leaves while custom modules are expanded. Proxy-dependent Python control flow can fail, and tracing sees only the branch resolved by the route. `torch.export` executes with examples and often lowers module hierarchy into ATen operations. Capture and `TracedModel.create` accept both positional `example_args` and named `example_kwargs`; named inputs are ordered against graph placeholders for ShapeProp, including keyword-only model parameters.

`GraphStructureQuery`, module classification, legacy shape maps, and many mutation actions still project the graph onto `call_module` nodes. Their pair traversals use functional nodes as connectors, not action endpoints. `LayerShapeAnalyser` historically used a single tensor probe; `TracedModel` now accepts actual `example_args` for multi-input and integer-input shape propagation. Parameter accounting includes module calls and direct `get_attr` parameters, deduplicated by identity.

## Region and interface model

`GraphRegionAnalyzer.discover(gm)` returns nested `RegionCandidate` records with FX-node entry/exit, internal nodes, all crossing input/output edges, structural reasons, and separate tensor-interface reasons. Boundary edges identify ordinary data, parameter/buffer, and metadata dependencies. They also preserve each operand occurrence path through tuples, mappings, and slices: FX's `Node.users` only records a source/destination pair, so `x + x` or an FX node reused as both slice bounds would otherwise hide operand positions. Dominator and postdominator forests identify candidate cuts. When a capture route preserves `nn_module_stack`, its hierarchy supplies additional nested cuts; `RegionCandidate.module_paths` records the hint paths, different node groups with shared endpoints remain separate candidates, and FX topology still validates each group. `GraphRegionAnalyzer.discover_nested(gm)` and `TracedModel.nested_regions()` also inspect nested GraphModules (including exported `torch.cond` arms) separately and record the owning `graph_path`; root action sites remain root-scoped until a branch-aware editor is available. Candidates that fail dominance checks are returned with an explicit rejection reason. This exposes decoder-layer and attention/MLP groups in Qwen export graphs without hardcoding their target names. Functional operations stay inside regions. Structured tuple/list/dict/custom-mapping values, namedtuple type information, scalar constants, and optional `None` values are retained. Unknown nested values include a path-specific interface rejection reason. Missing node metadata is now distinct from a real `None` value and marks the boundary as unanalyzed; parameter/buffer metadata is resolved from the owning GraphModule where possible. Tensor shape, dtype, device, layout, stride, and gradient metadata are represented when capture provides them.

`describe_linear_operations(gm)` provides operation-level descriptors for `nn.Linear` calls, `torch.nn.functional.linear`, `aten.linear`, and simple `addmm` projections whose matrix operand is a Parameter or its explicit transpose. It records input/weight/bias nodes, parameter target and aliases, orientation, and feature dimensions. `FunctionalLinearResizeAnalyzer` supports width growth for a narrow graph pattern: one functional or `addmm` projection, a single-use chain of known unary activations/identity/dropout operations, and one downstream functional or `addmm` projection. Stored `(in, out)` and `(out, in)` weight orientations are transformed separately. It also supports a gated multiply when both functional projection branches share the same input and output interface, one branch passes through a known feature-preserving unary operation, and the multiply feeds one downstream functional projection. The grouped plan resizes all branch outputs and the consumer input together, emits one action for the group, preserves trainable Parameters, refreshes value metadata throughout the affected user subgraph, and exposes rejection reasons for unsupported paths. Split/reshape/head layouts, other fanout or merges, module sinks, unknown shape metadata, and tied parameters remain rejected. Synthetic exported-graph tests cover gated resizing, sibling-branch fanout rejection, and an `addmm` producer-to-`linear` growth action that is generated and executed. A cached Qwen2.5-0.5B export run subsequently verified 24 functional width-growth actions, one for each gated MLP block; one action executed and returned finite logits with the expected output shape.

Structural representability is separate from interface analysis. Equal shapes alone do not prove semantic safety: aliasing, mutation, quantization, masks, parameter ties, and branch meaning may matter. Current regions are analysis results, not blanket approval to rewrite. Parameter/buffer `get_attr` edges are retained as explicit boundary inputs but excluded as activation-flow roots for dominance, so they do not make a functional projection look disconnected. The graph walk is iterative; region discovery handles a 10,000-node functional chain without recursion. Region cuts use canonical structural boundaries rather than every node pair.

`TracedModel.regions()` and `action_sites()` cache their analysis; `invalidate()` clears it after graph edits, and ShapeProp invalidates those caches after writing fresh node metadata. This matters when callers ask for action sites before requesting shapes: a later shape pass must replace stale “metadata missing” diagnostics. Action sites report missing metadata, unsupported structures, non-floating types, parameter/buffer values, and metadata-only consumers such as shape and dtype reads.

`analyze_feature_tensor()` turns tensor metadata into a feature-axis decision independently of graph structure. Sequential and residual low-rank action generators share this check. Its default policy supports rank-2 and rank-3 tensors on the final axis. A caller can supply one axis/rank policy or a per-rank mapping such as `{2: -1, 3: -1, 4: 1}` for mixed sequence and channels-first features; unknown or symbolic widths, unsupported dtypes, and unconfigured ranks return a reason instead of guessing.

## Graph transformations and action candidates

`ModelStructureEditor.insert_module_on_edge` inserts at an exact FX operand occurrence without requiring module-name endpoints. If a source appears more than once at a destination, callers must pass its `use_path`; omitting it is rejected instead of silently replacing every occurrence. FX sequential-linear and dropout actions retain these paths so they can rewrite one operand at a time. FX edits use the source value's dtype metadata and device metadata when available; ShapeProp's missing device can fall back to graph placement without overriding the edge dtype. Legacy name-based edits retain graph-parameter alignment. `RegionActionSite.meaningful_seam` centralizes the topology-only filter for module calls, recognized functional convolutions, and fan-out/merge points, avoiding each action generator implementing its own graph seam test. Functional Conv1d/2d/3d operators are recognized as useful boundaries; rank-4 convolution adapters still require an explicit feature axis and compatible tensor interface. `AddSeqLinearLayer` retains legacy module-pair proposals and adds low-rank feature adapters at eligible FX seams; ranks 4, 8, and 16 are bounded by feature width and a per-action parameter cap. Its default policy uses the last dimension for rank-2/rank-3 tensors and begins as identity. Callers can pass `feature_axis` and `supported_ranks` to enable other layouts, including rank-4 channels-first tensors; the adapter moves that axis to the final dimension for its linear operations, then restores it.

`AddResLinearLayer` retains only local legacy module-pair proposals and adds zero-initialized low-rank branches from existing operands at recognized FX sum nodes. It shares the same configurable `feature_axis` and `supported_ranks` policy. Python addition and exported `aten.add.Tensor` are recognized; in-place additions are excluded. Distant module pairs are rejected when another module lies between endpoints. `AddSeqDropoutLayer` uses region/action sites for dense functional graphs and retains the legacy traversal for smaller/module-oriented graphs; added modules inherit the GraphModule's training/eval mode. Actions store node names so they can be executed against copied graphs. Module-backed neuron resizing follows supported functional pointwise arithmetic. Functional `aten.linear` resizing is separately supported for a validated single-use unary chain between one producer and one downstream functional Linear. Both routes reject split, reshape, transpose, fanout, merge, tied-weight, and other unsupported boundaries with diagnostics. `linear_output_resize_rejection_reason()` explains module-backed cases; `functional_linear_resize_plan()` returns a plan or a specific rejection reason. Large-model growth can use a configurable added-parameter budget above a configurable model-size threshold; below that threshold the existing absolute matrix cap is preserved. Convolution candidates need a caller-verified spatial/channel-axis interface.

## Capture routes

`capture_graph(..., route="symbolic")` preserves the compatibility default. `ConfigurableTracer` allows caller-selected leaf module types; making a block a leaf hides its internals. `capture_graph(..., route="hf_symbolic")` uses Transformers `HFTracer` with example arguments. `hf_symbolic_editable` uses the Hugging Face `Conv1D` type, not module-name suffixes, to preserve and convert every such projection to `nn.Linear`. It keeps arbitrary leading dimensions intact because `nn.Linear` operates on the final feature axis; no capture-time flatten/reshape nodes or fixed output-width constants are added. This adapter still only handles models built with that projection type and is not a universal HF adapter.

`capture_graph(..., route="export", example_args=(...))` runs `torch.export.export` then re-roots its graph and attributes as a regular `fx.GraphModule`. This allows shared ShapeProp and editing APIs because the ExportedProgram-generated module itself rejects `train()`/`eval()`. Export requires representative inputs and may specialize behavior or lower user modules to ATen.

## Verified coverage

The latest graph-analysis update replaces per-entry postdominator-chain walks with one reverse-pass summary. A 256-module chain test verifies nearest boundaries and nested candidate discovery. A local stress check discovered 9,999 regions on a 5,002-node chain of 5,000 module calls in 0.185 seconds (region analysis only; not capture, action generation, or transformation). `pair_traversal_decision` bounds legacy reachability work and selects FX-region sites for large or functional-heavy graphs. A 1,000-Linear chain captured in 0.069 seconds and generated 999 sequential edge actions in 0.445 seconds; residual generation returned zero because the chain has no merge. The small ResNet path remains on legacy pairs under this policy. Large-graph convolution actions use rank-4 FX edge/merge adapters when callers explicitly provide a feature axis; functional-only convolution coverage verifies exact identity behavior across 44 functional operations with sequential and residual actions. The batch axis and non-floating interfaces are rejected. This explicit layout requirement prevents GPT-2 attention tensors from being mistaken for channels-first images. A 300-module spatial test executes sequential and zero-initialized residual convolution adapters with exact initial output equality. Small exported functional MLPs have synthetic coverage for GELU chains and gated multiply groups; both execute with finite gradients. Exported `torch.cond` branch GraphModules are now discovered separately with explicit graph paths; root action sites remain scoped to the root graph until branch-aware edits are implemented. On a fresh cached Qwen2.5-0.5B run, `torch.export` captured 1,861 nodes and eager/export logits matched. AddNeurons discovered 24 functional width-growth actions for gated MLPs; one was applied and produced finite logits with the expected `(1, 5, 151936)` shape. Attention reshapes, residual width changes, and tied embedding/LM-head edits remain unsupported. The GPT-2 regression most recently generated 1,753 proposals, including 24 neuron-growth actions and 957 shape-preserving linear/residual actions; representative linear/residual/dropout proposals preserved initial logits exactly. The full unit and integration suites pass 525 tests.

LFM3 received structural-only coverage via a temporary Transformers 5.12.1 overlay and no-op compatibility shims: its 1.728B-parameter meta model exported to 2,570 FX nodes, exposed 154 functional Linear projections, and produced 1,706 sequential-linear, 288 residual-linear, and 24 gated-MLP width-growth proposals at ratio 1.1. One width-growth action executed on a graph copy and retained logits interface shape `(1, 4, 128000)`. No checkpoint weights were loaded, so this does not establish numerical fidelity or normal runtime loading. The installed Transformers 4.45.1 environment remains incompatible with LFM3's custom source.

The latest full unit and integration run passed 521 tests. The 10,000-node chain test previously passed in 1.44 seconds in isolation. Importlib mode avoids a pre-existing duplicate test-module-name collection collision.

GPT-2 (`openai-community/gpt2`) was captured with `hf_symbolic_editable`: 591 FX nodes, 99 module calls, 49 rank-3 Linear calls, and 124,439,808 parameters in both original and traced models. Greedy token IDs matched and maximum logit error was `4.20e-5`. The latest rerun generated 738 sequential-linear, 258 residual-linear, and 774 dropout growth proposals. Functional pointwise width propagation plus the large-model parameter budget enabled 12 MLP neuron-growth proposals each at ratios 1.1 and 1.5; ratio 2.0 exceeded the budget. The JSON report records 36 width-resize rejections; each of the 12 fused attention QKV projections is explicitly rejected at its downstream split because head coordination is unsupported. On independent graph copies, representative sequential, residual, and eval-mode dropout actions preserved logits exactly (`max_abs_difference=0`); an MLP width-growth action returned finite logits with the expected shape. These are smoke checks, not proof that every proposal is semantically safe.

An untrained torchvision ResNet-18 smoke check captured 71 nodes and 60 module calls. With the default feature-axis policy it generated three legacy sequential-linear actions and no FX-edge linear actions for its rank-4 channels-first path, matching the legacy shape-based residual result. With explicit `feature_axis=1, supported_ranks=(4,)`, the same graph generated 54 FX sequential and 48 FX residual actions; one of each ran on an independent copy with finite output, the expected shape, and initial output equality. The ResNet integration suite also confirms existing train-mutate-train behavior.

A local-cache Qwen2.5-0.5B run on the current action path used explicit token IDs and `torch.export`, capturing 1,900 nodes. Eager and exported logits matched exactly (maximum absolute error `0.0`). Region discovery found 1,800 candidates and 2,329 action sites, of which 1,509 passed the current interface checks. It generated 1,240 sequential-edge and 288 residual-merge low-rank actions; representative edits executed on independent copies, preserved logits exactly, and returned finite output of shape `(1, 4, 151936)`. `AddNeurons` generated 24 gated-MLP growth actions at ratio `1.1`; a sampled action executed with finite logits and the same output shape. Full decoder groups cross at multiple activation inputs because of residual and positional values, so the analyzer reports those groups but rejects them as strict SESE regions. They are descriptive candidates, not safe-to-mutate approvals.

LFM3 could not load because its cached configuration requires Transformers 5.12.1 and imports `PreTrainedConfig`, while this project environment has Transformers 4.45.1. Its config declares 24 alternating convolution and attention layers, but the model graph has not been captured or verified. Multimedia and time-series models have not been captured. These are extension targets, not verified coverage.

## Limitations and extension points

- Add model capture adapters in `utils/fx/capture.py`; keep each route's specialization and failure diagnostics visible.
- Add feature-axis, aliasing, mutation, and symbolic-dimension providers before enabling more tensor layouts or safe width changes.
- Rewrites must account for every crossing edge, nested region, structured output, state, and tied parameter.
- Parent-graph analysis treats higher-order control-flow subgraphs as opaque FX nodes; branch-aware recursive analysis remains future work.
- Legacy sequential module-pair proposals can still span longer functional paths; neuron resizing and other width actions need FX-region implementations and diagnostics.
- No block duplication or deletion action was added.
